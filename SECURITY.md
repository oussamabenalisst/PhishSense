# Security Policy

## Supported Versions

Currently, we maintain security updates for the following versions of PhishSense:

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |

## Reporting a Vulnerability

We take the security of PhishSense seriously. If you believe you have found a security vulnerability, please follow these steps:

1. **Do Not** disclose the vulnerability publicly until it has been addressed.
2. Email your findings to <a href='https://www.linkedin.com/in/oussama-benali-ob/' > OussamaBenali </a>. Please include:
   - A description of the vulnerability
   - Steps to reproduce the issue
   - Potential impact
   - Any suggested solutions (if available)

### What to Expect

- We will acknowledge receipt of your report within 48 hours
- We will provide periodic updates about our progress
- Once the vulnerability is confirmed, we will:
  - Work on a fix
  - Release a security update
  - Credit you for the discovery (unless you prefer to remain anonymous)

## Security Measures

PhishSense implements several security measures:

1. Input Validation for all URLs and data processing
2. Secure data storage practices for analysis results
3. Regular security updates and dependency maintenance
4. Protection against common web vulnerabilities

## Best Practices

When using PhishSense:

1. Keep all dependencies up to date
2. Use HTTPS for all connections
3. Regularly check for security updates
4. Follow secure coding practices when contributing

## Dependencies

We regularly monitor and update our dependencies for security vulnerabilities. The project uses automated tools to check for known vulnerabilities in dependencies.
